## 它能做什么

| 能力 | 说明 |
| --- | --- |
| **一键获取 token** | 工作台点「**一键获取 token**」：自动扫描**电脑版微信**小程序进程内存取出 token（只读、不写内存、不注入、不需要管理员）→ 逐个验活 → 自动登录并读取真实数据，**全流程约 5 秒**，免去手工抓包 |
| **读取真实数据** | 用 token 读出：学生档案、**任务约束**（里程/拟合度阈值/速度与时长区间/生效时段）、**官方线路点列**、人脸与随机抽查开关、线路是否启用摄像头杆 |
| **开跑前门禁（三合一）** | 开场人脸 / 随机抽查 / 摄像头杆三项**在创建场次之前**判定；任一开启（或状态未读取）即停止并说明原因，**不会在你的账号上留下无效记录** |
| **线路按校区分组** | 任务下发的线路可能横跨多校区（实测南航 8 条分属 3 个地理簇，相距 10.8 km 与 90 km+），**且线路名称与坐标未必对应** → 按**坐标聚类**分组、本校区优先、跨校区标距离并给出警告 |
| **生成真实感轨迹** | 沿官方线路的走廊式轨迹：GPS 抖动 + **精度下降区**（拟合度闭环收敛到 **0.97~1.00**，贴近真跑、不是满分） |
| **数值不"一眼假"** | 里程**略超**任务要求 +0.3%~+4%（如要求 3.2 → 实跑 **3.21~3.33**）、配速非整分钟（如 `6'02"/km`）、时长随之自然（如 `00:20:34`） |
| **提交前自检** | 里程 / 拟合度 / 配速 / 时长 / 生效时段逐条对照任务约束，不合格就不提交 |
| **真实提交 + 回读判定** | `getRunBegin` → 真实等待（保证时间线经得起交叉验证）→ `sunRunExercises` + `sunRunExercisesDetail` → `getSunrunArch` 读回 `scorePassType` |
| **自由跑（可自设距离）** | 自由跑不需要任务：**距离由你自己设**（0.5~42.2 km，含 3/5/10/21.1 km 快捷档位），设过一次就会**记住**；按你描的跑道估算"约几圈"（不计入阳光跑成绩，与小程序一致） |
| **起跑点** | 在「跑道编辑」里**在地图上点一下**就能设起跑点（自动吸附到你选的那一道），可用滑杆沿跑道微调、并选择**顺时针/逆时针**；生成轨迹时**从该点出发** |
| **本地路线库（带编辑留痕）** | 每条路线记下**创建 / 最近保存的时间与所用版本**、**编辑次数**与**最近几次编辑历史**；可展开详情核对内外圈点数、周长、道次与起跑点坐标 |
| **演示（按需）** | 不想碰真实账号时，点「载入演示数据」用本地假数据看界面与报文（**不发任何请求**、不会真实提交）；默认界面**不含任何假数据** |

## 快速开始

### 方式 A：下载 EXE（最简单）

到 [Releases](https://github.com/dboycht/totoro-heaven/releases) 下载最新的 `totoro-heaven-<版本>.zip`，
解压后**双击 `totoro-heaven.exe`**：自包含 Node 运行时，**无需安装 Node.js 或任何依赖**，
启动后自动打开浏览器（`http://localhost:3000`）。Windows 10/11 x64。

### 方式 B：源码运行

```bash
npm install
npm run dev            # http://localhost:3000
npm run verify         # ★一键验证：单测 + 4 类类型检查 + 接线契约（改完代码先跑这个；CI 也会跑）
npm run test:mp        # 545 个单测（Node 内置 test runner，零依赖）
npm run typecheck:mp   # 纯逻辑模块类型检查
npm run typecheck:ui   # composables / src / utils / server 的 .ts 类型检查
npm run typecheck:vue  # .vue 模板类型检查（nuxi typecheck）
npm run check:wiring   # 接线与分层契约：门禁在写操作前 / 提交顺序 / 单一构造器 / 分层规则
npm run build          # 产出 .output/
npm run sea            # 打单文件 EXE（见 pack/sea/build-sea.ps1）
```

> 🤖 提交与 PR 会自动跑 `npm run verify`（见 [`.github/workflows/ci.yml`](.github/workflows/ci.yml)）。

## 使用流程

**第一步：拿 token（两种方式，任选）**

- **推荐：一键获取** —— 在**电脑版微信**里打开并登录「龙猫体育锻炼」，然后在工作台点「**一键获取 token**」：
  工具会只读扫描小程序进程内存取出 token（**约 5 秒**），自动验活、自动登录并读取真实数据。
  > 前提：**电脑版微信**（手机端没有该进程）；小程序需**已登录**且**保持开着**。
- **手动兜底：抓包粘贴** —— 用 Fiddler 抓一次小程序请求（系统代理 + HTTPS 解密），
  从任意一条 `wxxcx.xtotoro.com` 请求的 `Authorization: Bearer …` 里取出 token 粘到工作台。
   > ⚠️ **token 有效期只有几天**（实测：9-11 取的 token 到 9-14 已失效）→ 现抓现用。
   > ⚠️ 必须按 **host** 过滤（混杂抓包里按"最长"挑会挑到浏览器的 token）。

**第二步：读取与开跑**

2. **工作台**：点「**读取真实账号与任务**」→ 自动校验 token、识别学校、读取真实任务约束、
   官方线路与三个开关（人脸 / 随机抽查 / 摄像头杆）。
3. **阳光跑页**：选线路（**按坐标自动按校区分组、本校区优先**，跨校区线路会标出距离并给出警告）→
   「开始跑步」（模拟倍速，几十秒跑完）→ 看自检表 →「**真实提交**」。
   > 提交前会**真实等待**报备时长（约 20 分钟，可切页面），这是为了让
   > `endTime - startTime` 与服务器观测到的间隔一致；等待结束后自动提交并读回判定。

**前提条件**：① token 有效；② 学生本人**已在小程序里完成一次人脸建档**（未建档时开跑接口直接拒绝）；
③ 任务已下发；④ 开跑时间在任务时段内；⑤ 门禁通过（三类风控校验均未开启）。

## 技术要点

- **接口层**：57 个端点的元数据表（路径 / 方法 / 业务负载位置 / 是否需 token）。
  后端**没有统一信封**（`status`、`code`、`header.bizCode` 三轨并存），负载位置逐端点漂移；
  鉴权是 `Authorization: Bearer`，**必须始终携带**（无 token 时发 `Bearer null`），
  登录态失效的判据是 `header.bizCode == -199`（不是 401）。
- **多租户**：API 基址由学校清单的 `domainUrl` **按账号真实 `schoolCode` 解析**（共享域只是南航的值）；
  非共享域的学校会被明确拒绝——这既是技术边界，也是**有意为之的安全边界**。
- **开跑前门禁（三合一）**：开场人脸 / 随机抽查 / 摄像头杆三项**在创建场次之前**判定，
  任一开启（或状态未读取）都会停止并说明原因，**不会在你的账号上留下无效记录**。
- **校区分组**：任务下发的线路可能横跨多个校区（实测南航 8 条线路分属 3 个地理簇，相距 10.8 km 与 90 km+），
  且**线路名称与坐标未必对应** → 本项目**按坐标聚类**分组、本校区优先、跨校区标距离并给出警告。
- **拟合度**：官方路线每 5m 采样，采样点到用户轨迹折线的最短距离 ≤25m 记为命中，命中率即拟合度；
  任务阈值由服务端下发（南航实测 **0.60**），**判定在服务端**。
- **轨迹生成**：全局弧长推进（支持多圈/折返）＋ OU 相关抖动（ρ=0.92）＋
  按**路线弧长位置**定义的"精度下降区"（区长度可缩放），并用真算法**闭环控幅**把拟合度收敛到 **0.97~1.00**
  （依据：用户真跑实测 0.75）。
- **提交安全**：写操作只发一次、不重试；提交前自检；不使用任何服务端漏洞（如配置拉取失败的 fail-open）。
- **本地代理的上游白名单**：前端只与本站 `/api/mp/**` 通信，由服务端转发到学校 API。
  转发目标**只允许供应商自有域（`*.xtotoro.com`）且强制 HTTPS**——避免"上游地址由请求指定"演变成任意主机转发（SSRF），
  也避免把 `Authorization` 以明文 HTTP 发出去。

## 隐私与安全

| 项 | 做法 |
| --- | --- |
| **token 存放** | 只存**本机** `localStorage`（`mp_session`）；不打印、不入库、不上传 |
| **一键获取 token** | 只**只读**扫描**你自己**电脑上微信小程序进程的内存（`OpenProcess(PROCESS_VM_READ)`；**不写内存、不注入、不 hook、不需要管理员**）；扫描器与界面之间的结果只走**本机端点**（仅 loopback 可访问 + 一次性 nonce + 同源校验），token **不落盘、不打印**（只显示掩码与指纹） |
| **凭据转发** | 本地代理仅转发到你**学校的域名**（白名单 + 强制 HTTPS）；绝不把 token 送到其他主机 |
| **日志** | 事件日志与服务端文件日志**均只在本机**；token / 学号 / 姓名**一律脱敏**（掩码或只留长度），并有单测保证 |
| **XSS** | 全项目**不使用 `v-html` / `innerHTML`**，所有动态内容走 Vue 文本插值（自动转义） |
| **抓包存档** | 抓包文件（`.har`/`.saz`）与解析产物属于研究材料，`.gitignore` 已排除，**不进入仓库** |
| **不利用服务端缺陷** | 已知的服务端缺陷（如配置拉取失败即放行的 fail-open）**只记录、不利用** |

### 1.2.4（正式版）

- **新增「诊断」页**（顶栏「**数据**」组里，与「记录」「日志」并列）：遇到问题点「**开始记录**」→ 按顺序复现一次 → 点「**结束并导出**」，得到一个 zip。包里带你这次操作的**完整事实**：**任务的原始数据**（到底有没有下发线路/阈值）、本机路线库摘要、开跑前**门禁的判定依据**、你的**操作时间线**，以及**最近的服务器日志**（程序自己收集，不用去翻临时目录）。发给开发者即可对症修。**包里不含 token 明文**，学号与姓名也打码（导出前会先列出"包含什么"，日志里若出现形似凭证的内容会被自动排除）。
- **修掉两处"服务端没提、我们自己却当要求"的判据**（issue #12 实测反馈）：① 任务**没有下发拟合度阈值**时，以前按 0.6 硬判（自检表报红甚至拦提交）⇒ 现在按"本任务不判拟合度"处理，数值只作展示并标成**提示**；② 任务**没有下发线路**（不指定路线）时，以前被归因成"你还没描跑道"并被**门禁卡住** ⇒ 现在两者分开说明、不再阻断。
