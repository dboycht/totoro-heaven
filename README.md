# 龙猫天堂 · 阳光跑助手

面向 **微信小程序「龙猫体育锻炼」** 的校园跑辅助工具：读取真实任务与线路 → 用真实算法生成"像真人跑出来"的轨迹 → 真实提交 → 回读服务端判定。

> 与旧版无关：本仓库**只做微信小程序后端线**。早期针对旧 App 后端（`app.xtotoro.com`）的代码已在 1.1.1 轮次中**全部删除**，
> 仓库里不存在旧 App 的任何通道（扫码登录 / RSA 加密 / Cookie 透传代理）。历史版本见 tag `1.0.1`–`1.0.4`。

| 情况 | 是否支持 |

## 它能做什么

| 能力 | 说明 |
| --- | --- |
| **读取真实数据** | 用抓包得到的 token 读出：学生档案、**任务约束**（里程/拟合度阈值/速度与时长区间/生效时段）、**官方线路点列**、人脸与随机抽查开关、线路是否启用摄像头杆 |
| **生成真实感轨迹** | 沿官方线路的走廊式轨迹：GPS 抖动 + **精度下降区**（拟合度自然落在 0.94~0.98，不是满分） |
| **数值不"一眼假"** | 里程**略超**任务要求 2%~9%（如要求 3.2 → 实跑 3.41）、配速非整分钟（如 `6'02"/km`）、时长随之自然（如 `00:20:34`） |
| **提交前自检** | 里程 / 拟合度 / 配速 / 时长 / 生效时段逐条对照任务约束，不合格就不提交 |
| **真实提交 + 回读判定** | `getRunBegin` → 真实等待（保证时间线经得起交叉验证）→ `sunRunExercises` + `sunRunExercisesDetail` → `getSunrunArch` 读回 `scorePassType` |
| **演示模式** | 不填 token 也能看界面：全部用本地假数据，**不发任何网络请求** |

## 快速开始

### 方式 A：下载 EXE（最简单）

到 [Releases](https://github.com/dboycht/totoro-heaven/releases) 下载最新的 `totoro-heaven-<版本>.zip`，
解压后**双击 `totoro-heaven.exe`**：自包含 Node 运行时，**无需安装 Node.js 或任何依赖**，
启动后自动打开浏览器（`http://localhost:3000`）。Windows 10/11 x64。

### 方式 B：源码运行

```bash
npm install
npm run dev            # http://localhost:3000
npm run test:mp        # 92 个单测（Node 内置 test runner，零依赖）

npm run build          # 产出 .output/
npm run sea            # 打单文件 EXE（见 pack/sea/build-sea.ps1）
```

## 使用流程（真实模式，南航）

1. **拿 token**：在电脑上用 Fiddler 抓一次小程序请求（系统代理 + HTTPS 解密），
   从任意一条 `wxxcx.xtotoro.com` 请求的 `Authorization: Bearer …` 里取出 token。
   > ⚠️ **token 有效期只有几天**（实测：9-11 取的 token 到 9-14 已失效）→ 现抓现用。
   > ⚠️ 必须按 **host** 过滤（混杂抓包里按"最长"挑会挑到浏览器的 token）。
2. **工作台**：粘贴 token → 点「**读取真实账号与任务**」→ 会显示真实任务约束与一票否决项
   （人脸 / 随机抽查 / 摄像头杆）。
3. **阳光跑页**：切「**真实模式（南航）**」→ 选线路（默认自动选中与本人校区同名的那条）→
   「开始跑步」（模拟倍速，几十秒跑完）→ 看自检表 →「**真实提交（南航）**」。
   > 提交前会**真实等待**报备时长（约 20 分钟，可切页面），这是为了让
   > `endTime - startTime` 与服务器观测到的间隔一致；等待结束后自动提交并读回判定。

**前提条件**：① token 有效；② 学生本人**已在小程序里完成一次人脸建档**（未建档时开跑接口直接拒绝）；
③ 任务已下发；④ 开跑时间在任务时段内。

## 技术要点

- **接口层**：56 个端点的元数据表（路径 / 方法 / 业务负载位置 / 是否需 token）。
  后端**没有统一信封**（`status`、`code`、`header.bizCode` 三轨并存），负载位置逐端点漂移；
  鉴权是 `Authorization: Bearer`，**必须始终携带**（无 token 时发 `Bearer null`），
  登录态失效的判据是 `header.bizCode == -199`（不是 401）。
- **多租户**：API 基址由学校清单的 `domainUrl` 决定（本项目只用到南航的共享域）。
- **拟合度**：官方路线每 5m 采样，采样点到用户轨迹折线的最短距离 ≤25m 记为命中，命中率即拟合度；
  任务阈值由服务端下发（南航实测 **0.60**），**判定在服务端**。
- **轨迹生成**：全局弧长推进（支持多圈/折返）＋ OU 相关抖动（ρ=0.92）＋
  按**路线弧长位置**定义的"精度下降区"，并用真算法**闭环控幅**把拟合度收敛到 0.94~0.98。
- **提交安全**：写操作只发一次、不重试；提交前自检；不使用任何服务端漏洞（如配置拉取失败的 fail-open）。

## 风险与免责

校园跑小程序内置多重风控：**虚拟定位检测**（客户端判定）、**轨迹拟合度校验**（服务端判定）、
**随机人脸抽查 / 开场人脸**（服务端强校验，本地无法伪造）、**打卡点围栏**、**摄像头杆**、
运动传感器分析等。部分学校开启人脸抽查后，本方案**不成立**。

本项目**仅用于教育与研究目的**。请遵守所在学校的规章制度；作者不对任何使用后果负责。
